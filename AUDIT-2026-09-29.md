# AACB-003 release audit — 2026-09-29 (internally operated)

Focused release audit of the frozen v0.3.0 candidate. Audit-only: no
frozen file was modified, and no v0.3.1 was warranted — no substantive
correction (nothing changing conformance semantics) was found. All
findings are documented here and in the referenced addenda.

## 1. Deny-all: eight rows, three separate columns

Frozen-harness run of the deny-everything control against contract
v0.3.0, fresh scratch directory. Per-step correctness = verdict AND
reason AND observed effect-delta all match expected.

| row | expected verdict / reason / Δ | returned verdict | returned reason | harness-observed Δ | pass |
|---|---|---|---|---|---|
| S2  | ALLOW / ALLOW / +1       | DENY | DENY | 0 | FAIL |
| S4  | DENY / REVOKED / +0      | DENY | DENY | 0 | FAIL |
| S6  | DENY / REVOKED / +0      | DENY | DENY | 0 | FAIL |
| S8  | ALLOW / ALLOW / +1       | DENY | DENY | 0 | FAIL |
| S10 | DENY / STALE_OWNER / +0  | DENY | DENY | 0 | FAIL |
| S12 | ALLOW / ALLOW / +1       | DENY | DENY | 0 | FAIL |
| S14 | ALLOW / ALLOW / +1       | DENY | DENY | 0 | FAIL |
| S15 | DENY / REPLAY / +0       | DENY | DENY | 0 | FAIL |

Result: **ALLOW-half 0/4, DENY-half 0/4, NOT CONFORMANT.**
The G4 effect invariant also fails (0 effects across S14+S15, expected 1).

### Why precisely the DENY rows fail full conformance

Two independent facts, both from the frozen rule (SCORING.md: a step is
CORRECT iff verdict AND reason AND effect-delta all match):

1. The deny_everything driver's returned reason is `"DENY"`, deliberately
   outside the closed reason vocabulary (EXPECTED-003.md: `ALLOW`,
   `REVOKED`, `STALE_OWNER`, `REPLAY`) — its docstring states this is
   deliberate, "so no DENY row can be per-step correct either."
   Verdict-match alone is not correctness.
2. Conformance is a conjunction — 4/4 ALLOW **and** 4/4 DENY. The ALLOW
   half is 0/4 (the required harmless effect never appears), so the
   conjunction fails regardless of how the DENY rows score.

Either half at 0 fails the conjunction. Blocking everything fails
conformance by design: a system that never permits useful work is not a
conformant authority system.

### Wording-precision note (reported, not fixed)

SCORING.md's prose says a deny-everything driver "fails reason checks on
the DENY half." That is true of *this* control but not entailed by the
rule — a hypothetical deny-all driver returning DENY/REVOKED where
expected would score 4/4 on the DENY half and still fail via the
conjunction. No conformance semantics change; the prose stands as
written. This is a wording observation, not a correction.

### Reason-category audit: clean

The closed reason vocabulary is semantic — ALLOW, REVOKED, STALE_OWNER,
REPLAY — with zero OpenLine-specific wording in the harness or any
driver. Driver fallback reasons (MALFORMED, UNKNOWN_OWNER,
BAD_SIGNATURE, MISMATCH, UNKNOWN_GRANT) are generic authorization
terms. "OpenLine" appears only in COMPARISON-MATRIX.md (describing
OpenLine's own inspected suites, legitimate) and in "no OpenLine code"
labels.

## 2. Independent effect-observation proof

The frozen harness never uses the returned verdict to determine effects.
In `aacb-003-harness.py`, the `run()` attempt branch:

```python
def effects_len() -> int:
    return len(driver.effects())
...
elif op == "attempt":
    before = effects_len()
    verdict, reason = driver.attempt(*rargs)
    after = effects_len()
    delta = after - before
    ok = (verdict == exp_verdict and reason == exp_reason and delta == exp_delta)
```

The harness reads the driver's read-only `effects()` log itself —
before and after the attempt — and computes Δ independently. The verdict
string is one of three inputs to the correctness check, never the source
of the effect measurement.

### The false-reporting driver is caught purely through that observation

All 8 rows of the false_report driver return the correct verdict and
reason, but with inverted effects: ALLOW rows show observed Δ=0
(expected +1); DENY rows show observed Δ=+1 (expected +0). Shipped
evidence `evidence/fault-false_report/steps.jsonl`, S2:

> `"actual": {"verdict": "ALLOW", "reason": "ALLOW",
> "effects_before": 0, "effects_after": 0, "effect_delta": 0}`
> vs expected `effect_delta: 1` → `"pass": false`

Caveat (from run-results.md): the G4 invariant (exactly one effect
across S14+S15) passed numerically for false_report — the invariant is
necessary, not sufficient; the per-step deltas are what catch the false
reporter. The observation boundary is stated precisely in RELEASE-NOTES.md.
